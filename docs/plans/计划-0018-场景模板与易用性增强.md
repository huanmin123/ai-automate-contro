# 计划-0018-场景模板与易用性增强

## 背景

当前项目已经覆盖浏览器、桌面、HTTP、数据库、Excel、文件、控制流、AI 终端和调试修复等核心能力。继续单纯增加 action 的边际收益开始下降；更高频的问题变成用户需要理解 handbook、选择执行线、拼接多个 action、补验证和处理失败。

下一阶段应把现有能力组合成可复用场景模板，让用户可以从“我想抓后台表格并写 Excel”“我想清洗一个工作簿”“我想通过桌面文件对话框批处理”这类目标直接进入可运行 plan 包。

## 目标

- 建立官方场景模板机制，模板最终产物仍是普通 plan 包。
- 首批覆盖浏览器数据抽取、Excel 清洗报表、HTTP API、浏览器下载处理、SQLite 导入导出和桌面文件对话框批处理等高频场景。
- 让 `cplan create` 和 AI 终端都能基于模板生成 plan 包。
- 让模板有稳定示例资源、说明文档、校验和回归入口，避免模板随 action 演进腐烂。
- 降低用户需要直接理解 action 字段的比例，同时保持 JSON plan 可读、可改、可调试。

## 范围

第一阶段：

- 新增模板元数据和模板包存放约定，例如 `src/ai_automate_contro/plans/templates/` 或项目级 `templates/`，实现时按打包和发行包复用成本选择。
- 扩展 `cplan create`：
  - `--template <id>` 从模板创建 plan 包。
  - `--param key=value` 覆盖模板声明的变量；复杂值使用 JSON 对象或数组。
  - `--automation-type` 仍可用于空白 plan；使用模板时由模板声明默认执行线。
  - `--name` 继续覆盖生成的 plan 名称。
- 增加 `cplan template list` 或等价只读入口，列出模板 id、执行线、用途、需要用户补充的变量和是否可离线运行。
- 首批模板：
  - `browser-login-extract`: 浏览器打开页面、必要时人工登录、抽取表格或字段、写出 JSON/CSV/Excel。
  - `excel-cleaning-report`: 读取 Excel，多步 `table` 清洗、汇总、查表和写出报表。
  - `api-to-excel`: HTTP API 请求、JSON 数组筛选、写出 JSON/CSV/Excel。
  - `browser-download-process`: 触发浏览器下载 CSV，读取下载文件后清洗并输出报表。
  - `sql-import-export`: CSV 导入 SQLite，查询筛选，导出 Excel 和 JSON 报告。
  - `desktop-file-dialog-batch`: 桌面打开受控 App 或文件对话框，选择文件、保存结果、截图和断言。
- 每个模板生成完整 plan 包结构：`plan.json`、`config.json`、`resources/` 示例、`docs/README.md`。
- 新增模板 cookbook 文档，说明模板适用场景、必填变量、输出位置、默认是否可离线运行和扩展方式。

第二阶段：

- AI 终端增加模板优先的 plan 生成策略：
  - 先确认执行线：网页/URL 走 `browser`，本机 App/窗口/文件对话框走 `desktop`，纯文件数据处理可用普通 plan 承载 common action。
  - 按模板收集槽位：入口 URL、登录方式、输入文件、输出格式、数据库连接、桌面 App、目标窗口、风险确认等。
  - 对真实网站和真实桌面 App 仍必须先取证，不能因模板存在而跳过 `inspect_web_page`、探索 plan、`inspect_desktop` 或 `desktop_capture type=observe`。
  - 模板生成后自动走 `validate_plan`、`review_plan_quality`，必要时运行示例或探索 plan。
- `create_plan_package` 工具支持 `template_params`，与 `cplan create --param` 使用同一套模板变量校验。
- 更新 `ai-plan-generation` 自检，覆盖模板选择、槽位追问、歧义确认和风险确认。
- 增加失败诊断中的模板提示：当失败 plan 来自模板时，报告应指出模板步骤、用户应补充的信息和可修复候选。

第三阶段：

- 扩展模板库：
  - `api-to-excel`: HTTP API 请求、JSON 字段提取、表格化、写 Excel。
  - `sql-import-export`: CSV/JSONL/Excel 与 SQLite/服务数据库导入导出。
  - `browser-download-process`: 浏览器下载文件后读取、清洗并输出结果。
  - `desktop-chat-message`: 桌面聊天消息发送，收件人白名单、发送前确认和截图证据。
- 将高价值模板纳入发行包示例和快速使用指南。

## 设计约束

- 模板不是新 DSL。模板只负责生成当前 schema 下的普通 plan 包。
- 不引入旧字段、旧 action 名称或兼容分支；模板始终使用当前 action 契约。
- 模板中的示例必须可复现，默认使用本地资源、受控 HTML 或受控桌面夹具，不依赖真实网站、真实账号或真实业务 App。
- 真实网站、登录、验证码、权限、真实发送、真实写库和生产数据变更仍按现有 AI 终端证据和人工确认规则执行。
- 模板输出不能写入 `output/`、`profiles/` 或 `.keygen/` 的提交内容。
- 模板文档放在 cookbook/handbook 合适入口，不能把开发自检记录塞进 action 手册。

## 实施步骤

1. 设计模板元数据结构：`id`、`title`、`automation_type`、`description`、`variables`、`resources`、`docs`、`offline_runnable`、`risk_notes`。
2. 实现模板发现和复制逻辑，复用 `create_plan_package` 的目录创建、`config.json` 和执行线校验。
3. 扩展 CLI 参数和帮助文本，增加模板列表和模板创建入口。
4. 增加模板参数化创建，覆盖 CLI `--param` 和 AI 工具 `template_params`，并拒绝未声明的参数名。
5. 新增首批三个模板包，并确保生成后的 `plan.json` 可以通过 `cplan validate`。
6. 为模板生成后的示例资源补最小可运行用例；桌面模板默认使用受控窗口或静态示例，不依赖真实微信、QQ、Office 或游戏。
7. 新增 `template-components` 或并入 `release-matrix` 的模板校验步骤，覆盖模板发现、创建、校验和离线样例运行。
8. 更新 AI 终端提示词和 `ai-plan-generation` 自检，让模型优先选择模板并正确追问必要槽位。
9. 更新 README、快速使用指南、handbook 入口和测试说明。

## 风险

- 模板太抽象会退化成另一本 handbook；首批模板必须是端到端可运行场景，不只是一段 JSON 片段。
- 模板太具体会难复用；变量、资源和 docs 要明确哪些字段由用户替换。
- AI 终端可能因为模板存在而跳过真实网页/桌面取证；质量门禁必须继续要求证据。
- 桌面模板容易受本机焦点、权限和窗口状态影响；默认回归必须使用受控窗口，真实 App 作为显式验证。
- 模板复制和打包路径若处理不当，发行包可能找不到模板资源；实现时需要覆盖源码运行和打包运行两种运行根。

## 验收标准

- `cplan create --template browser-login-extract --path ...` 可以创建完整 plan 包，并通过 `cplan validate`。
- `cplan create --template excel-cleaning-report --path ...` 可以创建完整 plan 包，示例资源可离线运行并产出 Excel/JSON/CSV 中至少一种结果。
- `cplan create --template browser-download-process --path ...` 可以创建完整 plan 包，示例资源可离线运行并产出下载 CSV、JSON、CSV 和 Excel。
- `cplan create --template sql-import-export --path ...` 可以创建完整 plan 包，示例资源可离线运行并产出 SQLite 导入结果、查询 JSON、导出 Excel 和报告 JSON。
- `cplan create --template api-to-excel --path ...` 可以创建完整 plan 包，并带本地 API 服务脚本；`template-components` 会用随机本地端口启动该脚本并端到端验证 JSON/CSV/Excel 产物。
- `cplan create --template desktop-file-dialog-batch --path ...` 可以创建完整 desktop plan 包，并在支持环境下通过受控桌面样例验证。
- 模板列表入口能通过 `template list --verbose` 和 `template show <id>` 展示模板 id、执行线、用途、参数类型、预期产物和风险提示。
- 模板创建入口支持参数化覆盖，`--param active_status=Inactive` 或 AI `template_params={"active_status":"Inactive"}` 会写入生成 plan 的 `variables`，未知参数或类型错误会失败。
- `template-components` 或 release matrix 对模板发现、创建、校验、参数类型和可运行模板进行回归。
- AI 终端对浏览器、Excel 和桌面文件对话框三类需求能选择模板、追问缺失槽位、生成当前 schema 的普通 plan，并通过 `review_plan_quality`。
- 文档入口能让用户从 README 或快速使用指南找到模板列表、创建命令和每个模板的修改位置。

## 验证

```powershell
python -m compileall -q src main.py cplan.py
python .\cplan.py self-check handbook
python .\cplan.py self-check template-components
python .\main.py self-check ai-plan-generation
python .\cplan.py self-check release-matrix --only compileall,handbook,template_components,ai_plan_generation --fail-fast
```

如果模板校验入口并入既有自检，最终命令以实现后的 `python .\cplan.py self-check --help` 为准。
