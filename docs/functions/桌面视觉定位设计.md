# 桌面视觉定位设计

## 定位

`desktop_vision` 是桌面线的视觉兜底 action。当前只支持 `type=locate_image`，从屏幕、窗口、控件截图或已有图片中定位模板图，并输出可复用的屏幕全局 `bounds/point`、source 局部 `local_bounds/local_point`、坐标诊断和证据文件。

实际点击、滚动、拖拽仍交给 `desktop_input target=bounds_center`、`desktop_input target=candidate` 或控件级 `desktop_element`。`desktop_vision` 只算取证和定位，不直接执行操作。

## OCR 移除决策

结论：桌面线不再支持 OCR，不再提供 `desktop_vision type=locate_text`，不再探测 Tesseract、pytesseract、`tessdata.*`，也不再接受 `desktop.ocr` 配置。

原因：本项目的自动化目标是可复现、可验证、尽量接近 100% 稳定。OCR 在真实桌面场景中受字体、字号、语言包、缩放、主题、抗锯齿、截图清晰度、中英文混排和背景干扰影响，不能承诺关键流程所需的确定性。即使增加灰度、二值化、锐化、放大和置信度门禁，也只能提高部分截图的识别率，不能把 OCR 变成稳定组件。

后续原则：

- 不要把 OCR 作为 desktop action、能力矩阵字段、CLI 门禁、自检依赖或默认计划生成能力加回。
- 需要读取文字时，优先使用 `desktop_element get_text/get_state/get_table/get_tree`、应用 API/CLI、导出文件、数据库/文件读取或业务接口。
- 控件树不可读且文字是关键判断依据时，使用 `manual_confirm` 或让用户提供稳定结构化输入，不用 OCR 继续猜。
- 视觉兜底只保留图像模板定位，适合稳定图标、图片按钮、画布局部特征和已有截图中的固定图形。

## 使用优先级

1. 优先使用应用 API、CLI、导入导出能力。
2. Web 内容使用浏览器执行线和 Playwright selector。
3. 桌面 App 优先使用 Window Query + Element Locator。
4. 控件树不可见、自绘界面、画布、图标按钮、图片按钮或已有截图中需要定位稳定图形时，才使用 `desktop_vision type=locate_image`。
5. 视觉结果不稳定时使用 `manual_confirm`，不要凭猜测坐标继续操作。

## locate_image

```json
{
  "action": "desktop_vision",
  "type": "locate_image",
  "desktop": "desk",
  "template_path": "resources/save-button.png",
  "source_target": "window",
  "title_contains": "Demo",
  "window_match_index": 0,
  "threshold": 0.88,
  "match_index": 0,
  "max_matches": 10,
  "timeout_ms": 3000,
  "interval_ms": 250,
  "path": "save-button-match.json",
  "output": {"as": "save_button"}
}
```

## 参数

| 字段 | 作用 |
| --- | --- |
| `type` | 只能是 `locate_image` |
| `desktop` | 桌面 session 名 |
| `template_path` | 模板图，建议放在当前 plan 包 `resources/` |
| `source_path` | 可选，已有截图或图片；不能和 `source_target` 同时使用 |
| `source_target` | 可选，`screen`、`window`、`element`；省略且没有 `source_path` 时抓取当前桌面截图 |
| Window Query | `source_target=window/element` 时必填至少一种窗口定位字段 |
| `window_match_index` | 仅 `source_target=window/element` 使用，选择第几个窗口候选，默认 `0` |
| Element Locator | `source_target=element` 时必填至少一种控件定位字段 |
| `region` | 可选搜索区域；使用 `source_path` 时相对图片，`source_target=screen` 时相对屏幕，`source_target=window/element` 时相对窗口或控件截图 |
| `state` | 仅 `source_target=element` 使用，`exists/enabled/disabled/focused`，默认 `exists` |
| `threshold` | 图像匹配最低分，默认 `0.85`，取值 `0..1` |
| `match_index` | 多个命中时选择第几个，默认 `0`；不作为窗口候选索引 |
| `max_matches` | 最多保留的候选数量，默认 `10` |
| `timeout_ms` / `interval_ms` | 等待视觉目标出现 |
| `max_depth` / `max_elements` | `source_target=element` 的控件树遍历限制 |
| `path` | 写入 `output/desktop-vision/` 的 JSON 文件 |
| `output` | 保存 payload 到变量 |

## 能力矩阵

`capability_matrix.capabilities.vision` 暴露可用视觉能力，依赖放在顶层 `capability_matrix.dependencies`：

```json
{
  "capabilities": {
    "vision": {
      "image_locator": true,
      "template_matching": true
    }
  },
  "dependencies": {
    "Pillow.ImageGrab": true,
    "opencv-python": true,
    "pyautogui": true,
    "pyperclip": true
  }
}
```

缺少截图或 OpenCV runtime 时，AI 不应生成 `locate_image` plan。

## 坐标诊断

当前已统一输出：

- `coordinate_space`: `origin`、`unit`、`scale`。
- `source_bounds`: source 在屏幕全局逻辑像素中的位置和尺寸。
- `match.local_bounds/local_point`: source 内局部坐标。
- `match.bounds/point`: 屏幕全局逻辑像素。
- `coordinate_diagnostics.local_to_global_offset`: 从局部坐标换算到屏幕坐标的偏移。
- `coordinate_diagnostics.warnings`: 例如 `scale_unknown`、`negative_source_origin`。

完整 DPI/Retina/多显示器校准仍由 `CoordinateMapper` 承接；当前 Windows/macOS 回归验证结构和 `global = local + source_bounds.xy`。

## 风险

- 模板匹配受主题、缩放、语言、hover、disabled 状态和抗锯齿影响。
- `source_path` 离线图片会返回 `screen_clickable=false`，只能作为证据，不能直接点击当前屏幕。
- macOS 截图需要 Screen Recording 权限，控件操作还需要 Accessibility。
- 视觉定位失败必须保留原图、候选、分数和诊断 JSON，不能静默退化成猜坐标。
